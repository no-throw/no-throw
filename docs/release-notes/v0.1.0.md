# v0.1.0

The first release of `no-throw`: mark a function `/** @nothrow */` and a static
check refuses to let a throw escape it. Throwing is the default, non-throwing is
opt-in, and adoption is one function at a time.

Built to the locked design spec, [#30](https://github.com/no-throw/no-throw/issues/30).

## Install

```bash
npm install --save-dev @no-throw/eslint-plugin typescript-eslint
```

```js
// eslint.config.mjs
import nothrow from "@no-throw/eslint-plugin";
import tseslint from "typescript-eslint";

export default [
  ...tseslint.configs.recommendedTypeChecked,
  nothrow.configs.recommended(tseslint.plugin),
];
```

The preset takes your typescript-eslint plugin object rather than bundling one
of its own. Flat config refuses a plugin name registered twice with two
different objects, and every project with typed lint in CI has already
registered `@typescript-eslint` — so the preset registers the copy you are
already using, and there is nothing to collide with.

The [README](https://github.com/no-throw/no-throw#readme) teaches the adoption
ladder from there: install the preset, mark one seed, bridge until green, handle
the dependency floors, and — if you publish — ship a manifest.

## What ships

- **Two rules.** `nothrow/no-escaping-throw` carries the entire invariant —
  uncaught throw, unbridged call, fake bridge and float are distinguished by
  `messageId` and are never individually disableable, because a configuration
  that enforced half of it would still look sound. `nothrow/valid-mark` is
  annotation hygiene: a mark that binds to nothing is a hard error, never a
  silent no-op.
- **Zero rule options.** There is no configuration in which the guarantee means
  something different.
- **The whole escape surface.** Calls, `new C()`, `super()`, tagged templates
  and parameter defaults; and the hidden transfers — accessors behind a property
  read, dynamic keys, spread, coercion, `instanceof` — resolved through the
  static type rather than left as holes.
- **Async as one color over the whole surface.** A mark on a promise-producing
  function means it neither sync-throws nor rejects. `try { await f() } catch`
  is the universal bridge; a terminal `.catch(h)` with a non-throwing handler is
  the sanctioned fire-and-forget; `try { asyncFn() } catch` without `await` is
  reported as the fake bridge it is.
- **Generators, first class**, including the eager parameter list — a throwing
  default on `async function*` escapes at the call, though the body has not run.
- **Conditional cleanliness.** `users.map(u => u.name)` passes and
  `users.map(u => JSON.parse(u.raw))` is reported: the same call, judged on the
  callback you actually passed. Your own higher-order functions get the same
  treatment, with the condition read off your body rather than declared.
- **Shipped standard-library and DOM baselines**, keyed by lib target, so
  marking your first function does not produce a wall of errors on
  `Object.keys`. Generated inside a live `ts.Program` and gated by a hostile
  type-conformant fuzz run; a member with no entry has no color and floors, so a
  TypeScript release landing ahead of ours is safe by construction.
- **The full carrier chain** — local `nothrow.overrides.json`, installed
  `@no-throw/*` overlays, a dependency's shipped `nothrow.json` or its surviving
  `@nothrow` tags, then the baseline, then the floor — with hash-checked
  staleness and per-key precedence.
- **`nothrow emit` and `emit --check`**, which refuse to write a mark they
  cannot verify.
- **Diagnostics as a contract.** Every floor says why it floored and names your
  outs in precedence order, in the message text — the channel that survives into
  a CI log and a code review, never behind a docs URL. The plugin offers
  suggestions and **never an autofix**: wrapping a call in `try`/`catch` changes
  behavior, so the edit is always yours to accept.

## The dogfooding verdict: hybrid ships

Hybrid inference is the shipped default. #4 kept a lever to rip inference out
and degrade to pure declare — unmarked means throwing — and the pre-release
performance gate ([#47](https://github.com/no-throw/no-throw/issues/47)) was
the thing that would have pulled it.

Measured against **microsoft/TypeScript** at `b465fdbf` — 601 files, 379,646
lines, 12,326 function declarations, 36,566 call edges, and a condensation
containing one 1,189-member SCC — with 1,093 real marks:

| arm | cold, whole of `src` |
| --- | --- |
| baseline lint | 24.0 s |
| **hybrid (shipped)** | **33.0 s (+38%)** |
| declare-only | 30.3 s (+26%) |

By ESLint's own `TIMING`, `no-escaping-throw` costs 4.88 s hybrid against
1.79 s declare-only — so **inference itself is 3.1 s of a 33 s run, 9%**. A
third of what the preset adds is `no-floating-promises`, which the preset turns
on but does not implement. Warm and editor-shaped, the preset adds ~190 ms to a
~600 ms re-lint, of which inference is ~95 ms.

The walk saturates: over `src/compiler`, going from 100 marks to 1,093 grows it
by 7%. Cost is bounded by the reachable subgraph of the files being linted, not
by how deeply a codebase has adopted the tool.

The full report, its methodology and its two stated limitations are in
[docs/dogfooding-performance-gate.md](dogfooding-performance-gate.md). The
declare-only lever is not gone — it stays behind the color-resolution seam, and
the conformance suite runs a second time with inference off, asserting that
declare-only produces a **superset** of the hybrid run's diagnostics.

## What the guarantee is not

*No expected error escapes* — not VM-level totality. Programmer-bug
`TypeError`s, OOM and stack overflow still throw, exactly as `panic!` still
panics. And the guarantee is relative to the type system's model of your
program: where code lies to the checker — a `Proxy`, an `as` assertion, a wrong
ambient declaration — `no-throw` inherits the lie.

## Requirements

- Node ≥ 20.11
- TypeScript ≥ 5.0 and < 7.0. The ceiling is load-bearing: TypeScript 7 ships
  no programmatic compiler API, so an unbounded range would satisfy at install
  and fail at the first rule run.
- ESLint 9 or 10.

## Verification

Every gate green on the release commit: the conformance suite and its
declare-only superset run, the CLI suite, the §H diagnostics audit over every
normative message, both peer gates across every supported major, and the ES and
DOM hostile-fuzz, drift and deferred-invocation gates — each with its own
self-check, because a gate that cannot fail is not a gate.

The packages are published with npm provenance, so the tarballs are attested to
this repository at this commit.
